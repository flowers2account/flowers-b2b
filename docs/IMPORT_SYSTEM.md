## Обзор

### Что такое импорт остатков

**Импорт остатков** — это процесс загрузки данных из Excel-файлов поставщиков в базу данных платформы.

**Частота:** 2-3 раза в неделю (после каждой поставки)

**Источники:**
- **Голландия:** файлы типа `Срез_Голландия_ДД.ММ.ГГГГ.xlsx`
- **Китай:** файлы типа `Горшок_Китай_ДД.ММ.ГГГГ.xlsx`

**Тип импорта:** Обновление остатков (snapshot), а не новое поступление

## Структура XLS файлов

### Пример файла

```
┌────────────────────────────────────────────────────────┐
│ Стоимостная оценка склада в ценах номенклатуры         │
│ Период: на конец дня 21.05.2026                        │ ← Дата документа
├────────────────────────────────────────────────────────┤
│ Показатели: Количество (в ед. хранения)                │
├────────────────────────────────────────────────────────┤
│ Группировки строк: Склад (Элементы); Номенклатура      │
├────────────────────────────────────────────────────────┤
│ Отборы:                                                │
│   Склад B (Основной склад)                             │
│   Номенклатура B группе из списка (СРЕЗ ОСТАТКИ)       │
│   Срезка 19.05.2026 ← Дата прихода конкретной партии   │
└────────────────────────────────────────────────────────┘

┌─────────────────────────────┬───────────┬───────┬──────────┐
│ Склад                       │ Количество│ Цена  │ Стоимость│
├─────────────────────────────┼───────────┼───────┼──────────┤
│ Основной склад              │ 9 428,000 │       │          │
│   альпум гладиатор 85/90    │   2,000   │350,00 │   700,00 │
│   альстромерия микс белр... │ 160,000   │515,00 │82 400,00 │
│   антуриум гранд спам       │  12,000   │1750,00│21 480,00 │
│   ...                       │           │       │          │
└─────────────────────────────┴───────────┴───────┴──────────┘
```

### Ключевые поля

| Поле | Источник | Назначение |
|------|----------|------------|
| **Название товара** | Колонка "Склад" (вложенные строки) | → `products.name` |
| **Количество** | Колонка "Количество" | → `batches.stock` |
| **Цена** | Колонка "Цена" | → `batches.price` |
| **Дата прихода** | Строка "Срезка ДД.ММ.ГГГГ" (свёрнутая группа) | → `batches.arrival_date` |
| **Дата документа** | Заголовок "Период: на конец дня..." | Передаётся в функцию, но **НЕ используется** для UPDATE |

## Архитектура БД

### Таблицы

```sql
-- Справочник товаров (сорта)
products {
  id SERIAL PRIMARY KEY,
  name TEXT NOT NULL,                    -- Сырое название из XLS
  variety_id INT,                        -- Ссылка на сорт
  length_cm INT,                         -- Длина (60, 70, 80...)
  category TEXT,                         -- 'cut' или 'pot'
  
  -- Нормализация (для поиска)
  normalized_slug TEXT,                  -- Нормализованное название
  search_aliases TEXT[],                 -- Массив синонимов
  
  -- Отображение
  name_display TEXT,                     -- Красивое название для UI (будущее)
  image_url TEXT,
  is_active BOOLEAN DEFAULT true
}

-- Партии (физические остатки)
batches {
  id SERIAL PRIMARY KEY,
  product_id INT REFERENCES products(id),
  
  price NUMERIC NOT NULL,                -- Цена закупки
  stock INT NOT NULL,                    -- Остаток в штуках
  stock_reserved INT DEFAULT 0,          -- Зарезервировано
  
  arrival_date DATE NOT NULL,            -- ДАТА ПРИХОДА НА СКЛАД
  is_active BOOLEAN DEFAULT true,
  
  origin TEXT,                           -- 'china', 'holland', 'ecuador'
  farm TEXT,                             -- Название фермы-производителя
  
  created_at TIMESTAMPTZ DEFAULT NOW()
}

-- Агрегированный сток (для UI)
stock {
  id SERIAL PRIMARY KEY,
  product_id INT UNIQUE REFERENCES products(id),
  
  qty INT NOT NULL,                      -- Сумма всех batches.stock
  qty_reserved INT DEFAULT 0,            -- Сумма резервов
  price NUMERIC,                         -- Цена (из batches)
  is_available BOOLEAN DEFAULT true
}
```

### Связи

```
products (1) ←→ (N) batches
products (1) ←→ (1) stock
```

**Важно:** Таблица `stock` — это **кэш-агрегат** для быстрого доступа. Источник правды — `batches`.

## Функция sync_stock_from_1c

### Сигнатура

```sql
CREATE OR REPLACE FUNCTION sync_stock_from_1c(
  p_name TEXT,              -- Название товара из XLS
  p_new_qty INTEGER,        -- Количество из XLS
  p_new_price NUMERIC,      -- Цена из XLS
  p_arrival_date DATE       -- Дата из заголовка/группы XLS
) RETURNS void
```

### Алгоритм

```
┌─────────────────────────────────────────────────────────┐
│ 1. ПОИСК ТОВАРА                                         │
└─────────────────────────────────────────────────────────┘
   
   Шаг 1.1: Точное совпадение (case-insensitive)
   ↓
   SELECT id FROM products 
   WHERE LOWER(TRIM(name)) = LOWER(TRIM(p_name))
   
   Шаг 1.2: Если не нашли → нечёткий поиск (trigram)
   ↓
   SELECT id FROM products 
   WHERE similarity(name, p_name) > 0.85
   ORDER BY similarity DESC LIMIT 1
   
   Шаг 1.3: Если не нашли → создать новый товар
   ↓
   INSERT INTO products (name, is_active) 
   VALUES (p_name, true)

┌─────────────────────────────────────────────────────────┐
│ 2. ПОИСК ПАРТИИ                                         │
└─────────────────────────────────────────────────────────┘
   
   Ищем по (product_id, price) БЕЗ arrival_date!
   ↓
   SELECT id FROM batches
   WHERE product_id = v_product_id
     AND price = p_new_price
     AND is_active = true
   ORDER BY arrival_date DESC  -- самая свежая
   LIMIT 1

┌─────────────────────────────────────────────────────────┐
│ 3. ОБНОВИТЬ ИЛИ СОЗДАТЬ                                 │
└─────────────────────────────────────────────────────────┘
   
   Если партия НАЙДЕНА:
   ↓
   UPDATE batches
   SET stock = p_new_qty        -- ЗАМЕНИТЬ, не добавить!
   WHERE id = v_existing_batch_id
   
   ⚠️ arrival_date НЕ ТРОГАЕМ!
   
   Если партия НЕ НАЙДЕНА:
   ↓
   INSERT INTO batches (
     product_id, price, stock, arrival_date, is_active
   ) VALUES (
     v_product_id, p_new_price, p_new_qty, p_arrival_date, true
   )
```

### Ключевые особенности

#### ✅ **Что делает правильно:**

1. **Нормализованный поиск товара**
   - Игнорирует регистр: "Роза" = "роза"
   - Убирает лишние пробелы
   - Находит похожие названия (>85% сходства)

2. **Сохраняет `arrival_date` при UPDATE**
   ```sql
   -- ПРАВИЛЬНО:
   UPDATE batches SET stock = 20 WHERE id = 123
   -- arrival_date остаётся 19.05
   
   -- НЕПРАВИЛЬНО (старая версия):
   UPDATE batches SET stock = 20, arrival_date = '21.05' WHERE id = 123
   -- перезаписывает дату → теряется информация о реальном приходе
   ```

3. **Различает обновление и новую партию**
   ```
   Та же цена → UPDATE (корректировка остатка)
   Новая цена → INSERT (новая поставка)
   ```

#### ❌ **Чего НЕ делает:**

1. **Не деактивирует старые партии**
   - Если товара нет в XLS → партия остаётся `is_active = true`
   - Решение: отдельный скрипт для деактивации

2. **Не обновляет `stock` напрямую**
   - Триггеры пересчитывают автоматически
   - Если триггеров нет → нужно добавить

## Логика партионного учёта

### Что такое партия (batch)

**Партия** — это физическая поставка товара с:
- Конкретной датой прихода
- Конкретной ценой закупки
- Конкретным остатком

### Примеры

#### Сценарий 1: Обновление остатка

```
День 1 (19.05): XLS
  "Роза Red Naomi 60см | 100шт | 250₸"
  
→ Создаётся партия:
  batch #123: stock=100, price=250, arrival_date=19.05

День 2 (21.05): XLS (повторный импорт)
  "Роза Red Naomi 60см | 70шт | 250₸"
  
→ Партия обновляется:
  batch #123: stock=70, price=250, arrival_date=19.05 (НЕ 21.05!)
  
Причина: продали 30шт, дата прихода не изменилась
```

#### Сценарий 2: Новая поставка (другая цена)

```
День 1 (19.05): XLS
  "Роза Red Naomi 60см | 100шт | 250₸"
  
→ batch #123: stock=100, price=250, arrival_date=19.05

День 3 (21.05): XLS
  "Роза Red Naomi 60см | 100шт | 250₸" (старая партия)
  "Роза Red Naomi 60см | 50шт  | 300₸" (НОВАЯ цена!)
  
→ batch #123: stock=100, price=250, arrival_date=19.05
→ batch #124: stock=50,  price=300, arrival_date=21.05 (новая!)

В файле будет ДВЕ СТРОКИ с одним товаром, но разными ценами
```

#### Сценарий 3: Возврат/ревизия

```
День 1: stock=70
День 2: stock=90 (вернули 20шт или пересчитали)

→ UPDATE stock=90, arrival_date НЕ МЕНЯЕТСЯ
   (физически тот же товар, что пришёл в День 1)
```

## Нормализация названий

### Проблема

**В XLS приходят разные написания:**
```
"Роза Red Naomi 60см"
"роза red naomi 60см"
"РОЗА RED NAOMI 60СМ"
"Роза  Red Naomi  60см" (двойные пробелы)
```

Без нормализации → создадутся 4 разных товара!

### Решение

#### Уровень 1: Case-insensitive поиск

```sql
WHERE LOWER(TRIM(name)) = LOWER(TRIM(p_name))
```

**Эффект:**
- "Роза Red Naomi 60см" = "роза red naomi 60см" ✓
- Убирает пробелы по краям

#### Уровень 2: Trigram similarity

```sql
WHERE similarity(name, p_name) > 0.85
```

**Эффект:**
- "Роза Red Naomi 60см" ≈ "Роза Ред Наоми 60 см" (опечатки) ✓
- "Роза Red Naomi 60см" ≈ "Роза Red Naomi 70см" (другая длина) ❌

#### Уровень 3: Нормализованный slug (будущее)

```sql
products.normalized_slug = normalize_name(name)

normalize_name("Роза Red Naomi 60см")
→ "роза red naomi 60см" (lowercase + trim + убрать спецсимволы)
```

### Алиасы (синонимы)

**Проблема:** Один сорт может иметь разные написания

```sql
products.search_aliases = [
  'Red Naomi',
  'Ред Наоми',
  'Naomi Red',
  'RN60'
]
```

**Поиск:**
```sql
WHERE p_name = ANY(search_aliases)
   OR LOWER(name) = LOWER(p_name)
```

## Проблемы и решения

### Проблема 1: Дубли партий ❌ → ✅ Решено

**До исправления:**
```sql
-- При каждом импорте создавалась НОВАЯ партия
IF p_new_qty > v_current_qty THEN
  INSERT INTO batches (...) -- всегда INSERT!
END IF
```

**Результат:** 161 товар → 283 партии (дубли)

**После исправления:**
```sql
-- Проверяем: есть ли партия с такой ценой?
SELECT id FROM batches WHERE price = p_new_price ...

IF found THEN
  UPDATE stock = p_new_qty  -- обновить
ELSE
  INSERT INTO batches (...)  -- создать
END IF
```

**Результат:** 137 товаров → 190 партий (+ новые поставки разных цен)

---

### Проблема 2: Перезапись `arrival_date` ❌ → ✅ Решено

**До исправления:**
```sql
UPDATE batches 
SET stock = p_new_qty,
    arrival_date = p_arrival_date  -- ❌ перезаписывали!
```

**Результат:** Терялась информация о реальной дате прихода товара

**После исправления:**
```sql
UPDATE batches 
SET stock = p_new_qty
WHERE id = v_existing_batch_id
-- arrival_date НЕ ТРОГАЕМ! ✅
```

---

### Проблема 3: Точное совпадение названий ❌ → ✅ Решено

**До исправления:**
```sql
WHERE name = p_name  -- точное совпадение, case-sensitive
```

**Результат:** "Роза" ≠ "роза" → создавались дубли товаров

**После исправления:**
```sql
WHERE LOWER(TRIM(name)) = LOWER(TRIM(p_name))  -- case-insensitive
-- + fallback на trigram similarity > 0.85
```

## Чек-лист импорта

### Перед импортом

- [ ] Проверить структуру XLS файла (есть ли заголовок с датой?)
- [ ] Проверить наличие свёрнутых групп (дата прихода партии)
- [ ] Убедиться что колонки: Название, Количество, Цена

### После импорта

- [ ] Проверить количество партий: `SELECT COUNT(*) FROM batches WHERE is_active = true`
- [ ] Проверить дубли:
  ```sql
  SELECT product_id, price, arrival_date, COUNT(*) 
  FROM batches WHERE is_active = true
  GROUP BY product_id, price, arrival_date
  HAVING COUNT(*) > 1
  ```
- [ ] Проверить новые товары: `SELECT * FROM products ORDER BY created_at DESC LIMIT 10`

## Глоссарий

| Термин | Определение |
|--------|-------------|
| **Партия (batch)** | Физическая поставка товара с конкретной ценой и датой прихода |
| **Остаток (stock)** | Количество товара на складе |
| **Импорт остатков** | Загрузка данных из XLS в БД (обновление состояния склада) |
| **arrival_date** | Дата реального прихода товара на склад (НЕ дата документа!) |
| **Нормализация** | Приведение названия к единому формату для поиска |
| **Синонимы (aliases)** | Разные написания одного товара |
| **FIFO** | First In First Out — сначала продаём старые партии |
