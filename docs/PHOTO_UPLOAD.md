# Загрузка фото товаров — текущий флоу

## Где это работает

Вкладка **«Остатки»** в `/admin`. В каждой строке таблицы — два слота для фото:

| Слот | Поле в БД | Путь в Storage |
|------|-----------|----------------|
| Основное фото (левый) | `products.image_url` | `{slugify(name)}_{timestamp}.jpg` |
| Второе фото — кампанийное (правый, с красной рамкой) | `products.campaign_image_url` | `campaign_{slugify(name)}_{timestamp}.jpg` |

Оба слота проходят одинаковый флоу с remove.bg.

---

## Флоу загрузки (шаг за шагом)

```
Клик на миниатюру → выбор файла / съёмка камерой
        ↓
[Клиент] Сжатие если файл > 3.5 МБ (canvas, JPEG 88%)
        ↓
[Клиент] POST /api/admin/process-image  (multipart: file)
        ↓
[Сервер] Вызов remove.bg API
        ↓
    ┌───┴───────────────────────────────┐
    │ 200 OK                            │ 402 No credits
    │ Готовое фото на белом фоне        │ Исходный файл как есть
    │ Content-Type: image/jpeg          │ X-No-Credits: 1
    └───────────────┬───────────────────┘
                    ↓
[Клиент] Получает байты фото
        ↓
[Клиент] Удаляет старое фото из Supabase Storage (если было)
        ↓
[Клиент] Загружает новое фото в Storage (бакет product-images)
        ↓
[Клиент] UPDATE products SET image_url = <publicUrl> WHERE id = productId
        ↓
Миниатюра в строке обновляется мгновенно
```

---

## Почему загрузка идёт через клиент, а не сервер

Supabase Storage требует авторизованного пользователя для загрузки файлов. В serverless-функции на Vercel нет сессии пользователя (auth хранится в localStorage, не в cookies), поэтому загрузка из серверного route завершается ошибкой.

Решение: сервер отвечает **только за вызов remove.bg** и возвращает готовые байты. Клиент с активной сессией сам загружает результат в Storage.

---

## Серверный route — `/api/admin/process-image`

**Файл:** `src/app/api/admin/process-image/route.ts`  
**Runtime:** Node.js (не Edge — нужен FormData + бинарные ответы)

### Параметры запроса

```
POST /api/admin/process-image
Content-Type: multipart/form-data

file   — изображение (File)
```

### Параметры remove.bg

| Параметр | Значение |
|----------|---------|
| `image_file` | загруженный файл |
| `size` | `REMOVE_BG_SIZE` env (preview / auto) |
| `bg_color` | `ffffff` (белый фон) |
| `format` | `jpg` |

### Коды ответа remove.bg и поведение

| Код | Что происходит |
|-----|---------------|
| 200 | Возвращаем байты обработанного фото, `Content-Type: image/jpeg` |
| 402 | Кредиты закончились — возвращаем исходный файл + заголовок `X-No-Credits: 1` |
| 429 | Rate limit — один ретрай после `Retry-After` секунд |
| Прочие ошибки | JSON `{ error: "..." }` со статусом 502 |

---

## ENV-переменные

| Переменная | Где задать | Описание |
|-----------|-----------|---------|
| `REMOVE_BG_API_KEY` | Vercel + `.env.local` | Ключ API remove.bg. **Только сервер, никогда не в браузер** |
| `REMOVE_BG_SIZE` | Vercel + `.env.local` | `preview` — быстро, малый размер, меньше кредитов (для теста); `auto` — полный размер (для прода) |

## Кредиты remove.bg

- Free-план: **50 изображений** бесплатно
- При 402: фото сохраняется **без обработки**, под миниатюрой появляется жёлтое уведомление на 7 секунд
- Пополнение: [remove.bg/pricing](https://www.remove.bg/pricing)
- После пополнения ничего перенастраивать не нужно — всё заработает автоматически

**Проверить баланс:**
```bash
curl -s "https://api.remove.bg/v1.0/account" -H "X-Api-Key: <ключ>" | python -m json.tool
```

## Лимит размера файла

Vercel serverless ограничивает тело запроса **~4.5 МБ**. Чтобы не упираться в лимит:

- Файлы > 3.5 МБ сжимаются на клиенте через canvas перед отправкой
- Коэффициент сжатия вычисляется из соотношения размеров (≈ 90% от расчётного)
- Качество JPEG при сжатии: 88%

---

## Рекомендуемое соотношение фото

**1:1 (квадрат)** — карточка каталога имеет `aspect-ratio: 1/1`. Если фото прямоугольное — стороны обрезаются по центру.

---

## Хранилище

- **Бакет:** `product-images` в Supabase Storage
- Старое фото **удаляется** перед загрузкой нового (чтобы не копился мусор)
- Путь извлекается из URL через маркер `/product-images/`
