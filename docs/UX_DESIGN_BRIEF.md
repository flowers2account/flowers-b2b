# UX & Design Brief — Цветы Уральска B2B

**Продукт:** Оптовый B2B маркетплейс срезанных и горшечных цветов  
**Аудитория:** Флористы, цветочные магазины, корпоративные покупатели (Уральск, Казахстан)  
**Стек:** Next.js, Tailwind CSS, Supabase, Vercel  
**URL:** https://flowers-b2b-phi.vercel.app  

---

## 1. Кто пользователь

| Роль | Как работает | Ключевые задачи |
|------|-------------|-----------------|
| **Клиент** (флорист/магазин) | Заходит с телефона или десктопа, просматривает остатки, добавляет в корзину, оформляет заказ | Быстро найти нужный цветок → увидеть цену и остаток → заказать кратно пачке |
| **Менеджер склада** | Десктоп, внутренний инструмент | Подтвердить заказ, управлять остатками, загрузить XLS из 1С |
| **Владелец / Администратор** | Десктоп | Видеть все заказы, финансы, запускать предзаказные кампании |

**Контекст использования:** Клиент открывает сайт утром, когда менеджер залил остатки из 1С. У него 5–15 минут до открытия своего магазина. Скорость и ясность критичны.

## 2. Дизайн-система

### Палитра (брендбук)

| Название | HEX | Применение |
|----------|-----|------------|
| Rosewood (акцент) | `#8B3A5A` | CTA кнопки, активные элементы, цены |
| Bloom | `#C97A92` | Ховер состояния, вторичные акценты |
| Fern | `#3D6B50` | Зелёные бейджи (в наличии), иконки ухода |
| Petal | `#F5DCE4` | Светлые фоны, теги цветов |
| Blush | `#EEC9D4` | Мягкие заливки |
| bg-page | `#F6F2EF` | Фон страниц товара и каталога |

### Шрифты

| Шрифт | Назначение |
|-------|-----------|
| **Playfair Display** | Заголовки товаров (38px), брендовые элементы |
| **Golos Text** | Основной текст интерфейса, цены, кнопки |
| **Cormorant Garamond** | Латинские названия сортов (курсив), декоративные подписи |

### Принципы

- **Без лишних эмоций** — Premium B2B: никаких восклицательных знаков, цвет → факт
- **Плотность информации** — клиент видит 20–40 позиций на экране, карточка должна быть компактной
- **Кратность заказа** — pack_size везде на виду; цена за шт + цена за пачку

## 3. Каталог (главная страница)

### Текущая реализация

**Десктоп — три колонки (200px | 1fr | 280px):**

```
┌──────────────────────────────────────────────────────────┐
│  Header (навигация, поиск, корзина)                       │
├──────────┬───────────────────────────┬───────────────────┤
│  Фильтры │  Сетка товаров            │  Детальная панель │
│          │  [GridCard] [GridCard]    │                   │
│ Категория│  [GridCard] [GridCard]    │  пусто /          │
│ Цвет     │  [GridCard] [GridCard]    │  карточка товара/ │
│ Страна   │  ...                      │  корзина          │
│ Длина    │                           │                   │
└──────────┴───────────────────────────┴───────────────────┘
```

**Мобильный:** одна колонка + bottom sheet для фильтров и детальной панели.

### GridCard — что показывает

- Фото (с ховер-переключением на 2-е фото + точки-навигаторы)
- Флаг страны + ферма курсивом
- Название (display_name)
- Латинское имя сорта (если отличается от display_name)
- Цвет-кружки
- Цена за шт / кратность
- Бейдж «NEW» (arrival_date = сегодня), «АКЦИЯ» (previous_price > price)

### DetailPanel — три состояния

| Состояние | Что показывает |
|-----------|---------------|
| `empty` | Подсказка «выберите товар» |
| `detail` | Расширенная карточка: большое фото, описание, кнопка В корзину, sticky-шапка «← К каталогу» |
| `cart` | Список позиций корзины, итого, кнопка Оформить |

### Открытые вопросы для обсуждения

- **Переключение в корзину:** сейчас нажатие «В корзину» в детальной панели добавляет товар и остаётся в `detail` состоянии. Нужно ли автоматически переходить в `cart`?
- **Поиск:** сейчас в Header есть строка поиска. Поиск работает через `expand_search_query` (синонимы). Но визуально поиск и фильтры — отдельные системы. Как их объединить?
- **List/Grid переключатель:** есть ListRow компонент, но переключатель не всегда заметен. Нужен ли?
- **Сортировка:** нет явной сортировки (только по name + length). Нужна ли сортировка по цене, новизне, остатку?

**Десктоп — двухколонная:**

```
┌──────────────────────────────────────────────────────────┐

│                                                          │
│  Вкладка Описание:                                       │

│                              │  • Нидерланды             │
│                              │  • ...                    │

└──────────────────────────────────────────────────────────┘
```

### Открытые вопросы для обсуждения

- **Галерея:** у большинства товаров 2–3 фото с сайтов поставщиков. Не всегда отражают реальный товар. Нужен ли дисклеймер «фото для ознакомления»?
- **Цена за пачку:** блок с × pack_size появляется только если pack_size > 1. Нужно ли всегда показывать?
- **Кнопка «В корзину»:** сейчас кнопка показывает сумму (89 ₸ × qty). После нажатия — флэш «Добавлено». Нужна ли анимация перехода в корзину?
- **Похожие товары:** алгоритм — та же subcategory. Не учитывает цвет или диапазон цены. Улучшить?
- **Мобильная версия страницы товара:** галерея становится вертикальной (без sticky). Как должна выглядеть кнопка «В корзину» (sticky bottom bar)?

## 5. Корзина и оформление заказа

### Текущее состояние

- Корзина хранится в **Zustand** (localStorage, persist)
- Оформление — через DetailPanel (`cart` состояние) на главной
- Нет отдельной страницы корзины
- После оформления → заказ в Supabase, статус `pending`

### Открытые вопросы для обсуждения

- **Нет отдельной страницы корзины** — оформление происходит через правую панель. Это достаточно для B2B?
- **Нет email-подтверждения заказа** — клиент видит статус только в `/cabinet`
- **Резервирование 30 минут** — есть таймер? Клиент видит, что товар зарезервирован?
- **Минимальная сумма заказа** — не реализована. Нужна ли?
- **Оплата** — не интегрирована. Заказы подтверждаются менеджером вручную

## 6. Личный кабинет `/cabinet`

- Список заказов (pending → confirmed → cancelled)
- Предзаказы (campaign_orders) показываются выше обычных заказов
- Статус каждого заказа с датой
- Нет истории платежей, нет PDF-счёта

### Открытые вопросы

- Нужна ли возможность **повторить заказ** одним кликом?
- **Любимые товары** / wishlist — есть запрос от клиентов?
- Форматирование заказа для печати / WhatsApp?

## 7. Предзаказы / Кампании `/campaigns`

### Концепция

Менеджер создаёт кампанию (Европа / Китай), добавляет товары с ценами и датой доставки. Клиенты оформляют предзаказы в течение нескольких дней. По закрытию — один консолидированный заказ поставщику.

### Текущий UI

- `/campaigns` — список активных кампаний с таймером обратного отсчёта
- `/campaigns/[id]` — страница кампании: фильтры, карточки товаров, боковая корзина
- Поддержка гостей (имя + телефон без регистрации)

### Открытые вопросы

- Дизайн страницы кампании сделан отдельно от основного каталога. Нужно ли унифицировать?
- Таймер обратного отсчёта — насколько он мотивирует к действию в B2B контексте?
- Уведомления о новой кампании — пока не реализованы (ни WhatsApp, ни email)

## 8. Навигация и Header

**Двухуровневый sticky header:**
- L1 (58px): логотип + поиск + «Предзаказы» + корзина (счётчик + сумма)
- L2 (46px): категории-таблетки (Все / Срезанные / Горшечные / Расходники)

**Открытые вопросы:**
- Иконка корзины на мобильном — видна ли сумма?
- Нужна ли персонализация в хедере (имя клиента, «Добрый день, Алина»)?
- L2-навигация дублируется в FilterPanel — это нормально?

## 9. Аутентификация

- Вход по **телефону + PIN** (без email)
- PIN вводится вручную менеджером при регистрации клиента
- Нет самостоятельной регистрации — только через менеджера
- Нет сброса PIN (только через Supabase Studio или SQL)

**Открытые вопросы:**
- Это намеренное ограничение (B2B = только проверенные клиенты) или нужна самостоятельная регистрация с одобрением менеджера?
- Нет биометрии / Remember me — клиент каждый раз вводит PIN?

## 10. Администраторский интерфейс `/admin`

### Вкладки

| Вкладка | Описание |
|---------|---------|
| Остатки | Таблица всех товаров (AdminTable): поиск, редактирование, загрузка фото |
| Заказы | Kanban-доска: pending → reserved → confirmed → cancelled |
| Клиенты | Список клиентов, создание нового |
| Сотрудники | Управление профилями |
| Списания | Учёт брака |
| Инвентаризация | Сверка физических остатков |
| Кампании | Управление предзаказными кампаниями |
| Переводы | AI-переводчик накладных (bulk-страница) |
| Карточки | Генератор карточек товаров для WhatsApp |
| Касса | Режим кассира (pos-терминал) |

### Открытые вопросы

- Слишком много вкладок в одном месте — нужно ли разделить на несколько страниц?
- Kanban заказов — есть ли уведомления при новом заказе (браузерный push / звук)?
- Генератор карточек для WhatsApp — ключевой рабочий инструмент. Достаточно ли он удобен?

## 12. Нереализованные фичи (в roadmap)

- **Маппинг 1С → каталог** — `product_aliases` таблица: XLS-импорт сначала ищет алиас
- **WhatsApp уведомления** — при новом заказе, подтверждении, кампании
- **Фильтр «Только с фото»** — нет такого фильтра
- **Пакетное редактирование** цен/остатков в AdminTable
- **Печатная форма заказа** — PDF со складским форматом
- **Аналитика** — нет дашборда продаж, нет top-товаров

## 13. Технические ограничения, влияющие на UX

| Ограничение | Влияние на UX |
|-------------|--------------|
| Нет real-time (Supabase Realtime не подключён) | Клиент видит устаревшие остатки |
| Serverless Vercel — нет Service Role Key | Некоторые операции требуют обхода через клиент |
| Один проект Supabase для prod и dev | Нет staging — правки сразу в prod |
| Фото с сайтов поставщиков (Google Images) | Могут не совпадать с реальным товаром, могут удаляться |

## Вопросы для консультации

1. **Архитектура каталога:** 3-колонная раскладка vs отдельная страница товара — что лучше для B2B флористики?
2. **Мобильный сценарий:** 70% B2B клиентов работают с телефона. Как должна работать детальная панель на мобильном (сейчас bottom sheet)?
3. **Информационная плотность:** карточка сейчас показывает 6–8 полей. Что убрать, что добавить?
4. **CTA и конверсия:** кнопка «В корзину» — достаточна ли обратная связь после нажатия?
5. **Корзина:** нужна ли отдельная страница корзины или текущий подход (right panel) адекватен?
6. **Онбординг:** новый клиент впервые заходит — есть ли подсказки? Нужны ли?
7. **Брендинг:** Rosewood/Fern палитра — соответствует ли ожиданиям клиентов-флористов?
